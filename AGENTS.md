# Gadget SDK foundation

This is the independent public SDK repository. The licensed foundation was
bootstrapped at 42deb4e on staging/main; subsequent changes use feature branches
and PRs against staging. Never commit or push directly to main/staging.
Package publication is gated on
source/dependency audit and release verification. The owner approved Apache-2.0
for the SDK and reviewed extracts on 2026-09-08. Do not import private API
or Studio modules, copy their history, or embed credentials/customer fixtures.

Use apply_patch for source edits. Keep packages framework-neutral unless their
explicit purpose is presentation. No auth engine, real agent loop, permission
engine, credentials or direct production connections belong here. Typed
capability metadata never grants authority. Fixtures must be explicitly marked
and cannot silently fall back to live transport. Tests must stop owned processes.

Three component systems share one vocabulary by contract, not by code reuse:
Studio `@agenticos/ui` (Svelte, the design source of truth), the design board
under design-plans (the approved static reference), and `packages/shell`
(bot-* CSS primitives + framework-neutral `client/` modules for sandboxed
gadget canvases). A canvas reuses names, tokens and state contracts — never
the host's implementations, which it cannot load inside its `srcdoc` iframe.
When a canvas needs a component that exists only in Studio, report the gap
back rather than patching around it. `packages/shell/README.md` carries the
canonical description.

## Why the bots forked devkit — read before converging anything

Both gadget bots carry near-identical `scripts/` copies that devkit was
supposed to own. The divergence was rational, and a convergence that ignores
the reasons becomes the fifth copy. From the repos' history:

- **devkit could not build these packages.** `buildPackage(directory)` reads
  `manifest.json`, `definition.json` and flat `src/` members. The bots' shape
  — `manifest.json` packed *inside* the archive, `client.js` generated by a
  bundler, the definition authored as `definition.ts` — is a package devkit
  has no contract for. "Just use devkit" was never an option; the capability
  did not exist upstream.
- **Publish latency versus a same-commit fix.** Social added
  `assertPackedImports` on 2026-09-13 (`e9f6a2e`, after a shipped
  missing-member defect) and `assertStorageSchemaDeclaration` the same day
  (`bb28bf0`). Each was one local commit. The devkit path was SDK PR →
  staging CI → `npm-release` approval → publish → bot dependency bump → API
  re-vendor. Days versus minutes is how a fork beats a platform.
- **Discoverability.** `bot-email-campaign` bootstrapped by copying social's
  `scripts/` wholesale (`2681860`) — the repo shipped with no `AGENTS.md` or
  `README.md` naming devkit/testkit as the owner of these concerns.

The lesson is not "don't fork" — it is "make extending upstream the cheap
path, and make the fork visible when it happens anyway."

## Best practice for every gadget from here on

- **Derive, do not re-declare.** Filter tabs project the definition's enum;
  the renderer's branches are checked against the declared types; a list kept
  by hand is a bug waiting for the next value.
- **Port, never snapshot.** A vendored definition is re-ported from the
  branch it came from, through the provenance-tracked sync and its `--check`
  gate.
- **Extend upstream, do not fork.** If the SDK does not do enough, the fix is
  a devkit/testkit PR and a publish — never a local copy with the difference
  added. If that is too slow, the slowness is the bug to fix.
- **Consume packages as dependencies**, never by `BOT_SDK_SOURCE` path.
- **One entry artifact, split source.** `client.js` is bundled from
  `src/src/client/*.js`; the sandbox loads exactly one file.
- **Bundling stays bot-side — that is deliberate, not un-migrated.** Each
  bot keeps its own `client.mjs` (esbuild config, Svelte compile options,
  banner/minify choices) because those settings are per-bot: devkit owns
  the archive contract and hands `client.js` to `buildPackage` as a
  generated member — the bundler itself is the bot's own.
- **No bot names in generic packages.** Hostnames, keys and labels are
  caller-supplied.
- **Continuity and parity tests read both sides from source.** A test that
  mocks the seam it protects is decoration.
- **Build before test.** Lifecycle tests print child stderr.
- **Byte budgets are ratchets, not targets**, pinned at measured values with
  a comment saying what they guard.
- **Three design systems, one contract.** `@agenticos/ui` (Svelte),
  `design-plans/ui-components-board` (compiled Tailwind specimens) and
  `bot-shell` (CSS for iframes) cannot share code because a gadget iframe
  cannot run Studio's Svelte. Match names and contracts across them; do not
  attempt shared implementation.
